# EchoMind 工程案例

## 1. 背景

EchoMind 是一个面向客服场景的多 Agent 编排系统。系统需要在同一条请求链路中处理意图识别、Agent 路由、知识检索、工具调用、会话记忆和质量评测。工程工作的重点不是增加更多提示词，而是让每一步都能被观察、验证和降级。

## 2. 请求如何流转

一次请求进入 `/chat` 后：

1. 意图识别器综合 LLM、Embedding 和规则 Pattern，输出意图、意图组、置信度、紧急度与实体。
2. Orchestrator 根据意图、关键词、实体和运行状态计算领域分数，选择主 Agent 与辅助 Agent。
3. RAG 门控决定是否检索知识库；问候、明确转人工等请求跳过检索。
4. 业务类请求通过 ChromaDB 召回候选片段，再执行领域过滤、去重和证据校验。
5. Agent 综合知识证据、Skills、工具结果和分层记忆生成回答。
6. API 返回回答以及路由、工具、知识库使用和阶段耗时等调试信息。

## 3. 主要工程改进

### 3.1 中文向量检索

原链路在 Windows 环境下缺少稳定的本地中文 Embedding。工程改进接入 `BAAI/bge-small-zh-v1.5`，使用新的 ChromaDB collection 写入向量，同时保留旧 collection 作为回滚路径。

默认检索使用本地向量路径，减少不必要的外部模型调用；查询改写和 LLM 重排作为增强模式按需启用。

### 3.2 RAG 门控与证据约束

无差别检索会增加延迟与噪声。系统先根据意图判断是否需要业务知识，再按 Agent 领域约束候选文档。

对于退款、发票和重复扣款等高风险场景，如果没有与当前意图匹配的证据，链路采用失败关闭策略，不让模型自行补全政策内容。订单查询文档也不能被当作重复扣款证据。

### 3.3 多 Agent 路由

General、Technical 和 Billing Agent 的职责、工具和风险边界不同。路由结果使用结构化字段表示主 Agent、辅助 Agent、路由原因和置信度。

对于“登录故障并且重复扣款”等复合问题，系统支持 Billing 与 Technical Agent 并行处理后合并结果。是否转人工由结构化字段决定，避免从自然语言回答中误判。

### 3.4 记忆与隔离

- Redis 保存当前会话的工作记忆，并控制 TTL、窗口和压缩顺序。
- ChromaDB 保存可检索的历史摘要与用户画像。
- 用户和会话标识参与查询过滤，避免跨用户、跨会话串数据。
- 同步向量库操作放入线程池，降低阻塞异步主链路的风险。
- Redis 短时不可用时降级为无工作记忆模式，不阻断本次客服回答；ChromaDB 读取失败同样返回空的长期记忆上下文。

### 3.5 工具治理与可观测性

内部工具层封装参数校验、TTL 缓存、超时、熔断和 fallback。工具轨迹区分系统确定性预取与模型主动调用，便于解释一次回答为什么使用了某项数据。

`MCPToolManager` 是项目内部的工具管理抽象，不宣称已经实现完整的标准 MCP Server/Client 协议。

## 4. 评测方法

固定端到端基准为每个场景提供人工预期：

- 细粒度意图；
- 主 Agent 与完整路由；
- 是否应使用知识库或转人工；
- 回答必须满足的业务契约；
- 允许的前台模型调用范围。

测试同时记录外部延迟、工具轨迹和应用层模型调用次数，并输出机器可读 JSON 与 Markdown 报告。

## 5. 当前实测

2026-10-26 使用当前 Top-3 Evidence Selector 链路重新运行固定综合基准，共 7 个场景、8 次真实请求，全程使用 `qwen3.7-plus`：

| 指标 | 结果 |
|---|---:|
| 意图匹配 | 6 / 8（75.00%） |
| 主 Agent 匹配 | 7 / 8（87.50%） |
| 完整路由匹配 | 6 / 8（75.00%） |
| 回答契约通过 | 6 / 8（75.00%） |
| 严格端到端通过 | 5 / 8（62.50%） |
| P50 外部延迟 | 34.55 s |
| P95 外部延迟 | 68.00 s |
| 最大外部延迟 | 81.28 s |
| 前台模型调用 | 19 次，平均 2.38 次/请求 |

当前基线定位出三个后续优化方向：问候意图稳定性、技术与账单复合请求的 Billing 召回，以及“记住订单号”与政策查询的任务分流。本轮保留原始标签和单次运行结果，为后续独立冻结集验证提供对照。

分层冻结评测还包括：95 条意图集准确率 98.95%、60 条检索集 BGE Hit@1 97.22%，以及 24 条 Grounded Chat 集严格证据选择准确率 87.50%、项目负责人确认的回答事实忠实度 83.33%。各项指标对应不同数据集和评价目标，并按各自样本范围独立解读。

## 6. 下一阶段验证计划

- 使用人工评分样本校准 LLM-as-Judge 的一致性。
- 增加并发、限流和长时间稳定性测试。
- 针对当前 3 个综合回归发现开展优化，并使用新的独立冻结集验证。
