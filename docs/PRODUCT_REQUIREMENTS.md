# EchoMind 需求与验收说明

更新日期：2026-11-07。本文按当前实现和已完成评测整理需求、用户流程与验收条件。

## 1. 产品定位

面向产品咨询、技术故障、账单售后和人工交接的 AI 客服原型。需求输入包括项目定义的客服场景、六份演示知识文档、冻结评测中的实际回答，以及质量与性能对照结果。

| 目标 | 衡量方式 |
|---|---|
| 用户一次表达的主要诉求得到回应 | 分项覆盖检查、完整回答验收 |
| 政策类回答有直接依据 | 证据选择、事实忠实度复核 |
| 资料不足时给出明确下一步 | 知识缺口分类与核实路径 |
| 运行问题可定位 | Trace、阶段耗时与模型调用记录 |
| 平衡质量和计算消耗 | 固定质量标准下的 Token、延迟配对对照 |

## 2. 用户故事与功能需求

| 编号 | 用户故事 | 系统行为 | 验收条件 |
|---|---|---|---|
| F01 | 用户咨询退款审核与到账时间 | 识别退款诉求，检索并确认退款政策 | 区分申请后的审核时间、审核通过后的到账时间，保留工作日单位 |
| F02 | 用户反馈登录 401 | Technical 基于文档提供排查步骤 | 说明认证失败，给出凭证检查或重置路径，扩展建议明确标记 |
| F03 | 用户同时问配送费用和退款时效 | 拆分子问题，分别检索并整合 | 两项诉求分别有来源、均在回答中体现 |
| F04 | 用户询问文档未覆盖的发票时限 | 标记资料缺口，说明核实路径 | 回应时限诉求并引导业务入口或人工核实 |
| F05 | 用户明确要求人工处理 | 进入 Escalation 并组织交接信息 | 返回结构化升级状态与交接摘要 |
| F06 | 用户补充订单号 | 识别信息补充任务并保存本轮消息 | 明确确认收到，后续对话能结合历史理解 |
| F07 | 用户连续追问 | 读取当前会话与相关历史 | 在匹配的用户、会话上下文中处理请求 |
| F08 | 维护者更新客服规则 | 加载 Markdown/JSON Skills | 重载后对应 Agent 使用新规则 |
| F09 | 维护者复盘错误回答 | 按请求标识查看 Trace | 可查看意图、主辅职责、工具、证据与阶段耗时 |

退款、订单等真实业务操作的集成按独立接口实施；当前 F01–F09 的操作交付为信息说明、核验建议和交接摘要。

## 3. 核心流程

1. 输入消息，读取用户与会话上下文。
2. 识别意图、实体、紧急度及任务类型。
3. 选择业务职责，决定是否需要检索、工具和 Skills。
4. 对明确的复合诉求拆分子问题，分别检索与选择证据。
5. 根据逐项证据状态组织回答：提供已核实事实，给出待核实部分的下一步。
6. 返回回答、结构化路由和 Trace，保存本轮记忆。

## 4. 异常与状态设计

| 状态 | 用户侧行为 | 运行记录 | 验收重点 |
|---|---|---|---|
| 文档足以回答 | 根据选中依据说明规则 | 选中文档、证据状态 | 数字、条件、时间单位一致 |
| 主题相关但依据不足 | 说明需核实的具体事项 | 知识缺口状态 | 回应用户问题并给出下一步 |
| 一部分有证据 | 已确认部分正常回答，其余分别说明 | 每个子问题的状态 | 已支持项和缺口项均被覆盖 |
| 证据选择超时或解析失败 | 对尚待确认的事实提供核实路径 | 超时、解析与供应商错误类型 | 用户收到清楚响应，错误可定位 |
| 工作记忆不可用 | 使用本轮消息继续处理 | Redis 异常与降级状态 | 基础对话保持可用 |
| 用户明确转人工 | 整理当前诉求和已知信息 | 升级标志与交接摘要 | 交接信息可继续使用 |

## 5. 指标与当前证据

| 指标 | 定义 | 当前证据 |
|---|---|---|
| 意图准确率 | 标签完全匹配数量 / 评测数量 | 95 条、19 类冻结合成样本，94/95 正确 |
| 检索 Hit@1 | 正确文档排名第一的查询占比 | 36 条有答案查询，BGE 为 35/36 |
| 严格证据选择 | 有答案选对指定文档，缺口正确识别 | Grounded Chat v2 为 21/24 |
| 首次回答严格通过 | 同时满足事实、覆盖、操作真实性和安全 | 60 条修复前覆盖基线为 27/60 |
| 定向任务完成 | 受影响用例满足原验收目标 | 四条已知复合诉求，两组各 4/4 |
| Token 消耗 | 所有已返回 usage 的前台与后台调用之和 | 性能配对中 36,817 → 22,099 |
| 用户任务完成率 | 参与者成功任务数 / 已尝试任务数 | 按产品验证方案采集 |
| 用户任务用时与可信度 | 任务时间与 1–5 分可信度评分 | 按产品验证方案采集 |

## 6. 本轮产品决策记录

| 观察 | 决策 | 验证 | 后续 |
|---|---|---|---|
| 中文口语问法召回不足 | 采用中文 BGE 并分 collection 管理 | 60 条检索集对照 | 扩展政策与近似主题 |
| 复合请求漏答 | 子问题独立检索、并行选证 | 四条定向回归 | 扩展省略、弱分隔符和更多主题 |
| 结构化任务产生较多思考 Token | 三类任务关闭思考，最终回复保留 | 隔离四题配对，质量均通过 | 扩大请求类型并交错运行 |
| Judge 给分偏宽 | 采用人工复核验收、Judge 辅助诊断 | 双人参考与 16/8 校准分析 | 强化事实错误识别 |
| 可用性证据尚待采集 | 准备五个固定任务和记录表 | 测试方案与汇总工具 | 组织首轮参与者观察 |
