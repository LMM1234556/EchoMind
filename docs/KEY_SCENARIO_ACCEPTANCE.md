## 执行与记录

2026-11-15 已执行原清单 1/8 个场景：key-001 退款审核与到账。实际回复分别说明审核需 1–3 个工作日、审核通过后 5–7 个工作日退回原支付账户；助手逐项核对符合当前文档，项目负责人复核待确认。后端总耗时 24,398.8 ms，前台记录 3 次应用层模型调用。完整回复与 Trace 见[首轮原始记录](../backend/evaluation/reports/key_001_first_run_20261115.json)。

场景 key-002 的标点变体已单列保存原始失败和两次真实定向复测，见[回归记录](COMPOSITE_PUNCTUATION_REGRESSION_20261115.md)。本记录按变体单独验收，原清单逐题运行状态保持各自记录。

每次实际运行使用新的用户、会话和运行编号，记录代码版本、知识快照、模型配置、原始回复、Trace、耗时及供应商 usage。多轮场景在组内复用同一会话，组间保持隔离。

对于最终模型回答，逐项核对事实、覆盖、操作真实性和安全。故障注入检查使用可控替身，单列工程验证结果。运行异常与预算停止单列保留。计划场景、工程检查和实际模型结果各自记录状态。

本次已完成评测输入与展示的工程改进，最终模型回答和人工结论按实际运行结果填写。当前版本核验进度见[项目进展](PROJECT_PROGRESS_20261113.md)。

## 评测工作台

- 意图按正确标签数 / 样例数统计。
- 对话按有效辅助评分、评分异常和待人工验收分别统计。
- 用例可通过 `/eval/run` 提供 `case_id`、`reference_evidence` 和 `acceptance_criteria`。
- 内置演示用例使用版本化业务文档作参考；自定义用例按其提供的证据与量表评分。
- 默认用户与会话每次生成新标识；需要连续上下文时可显式设置。
- 评分均分统计有效评分，评分异常保留在对话计数中。
- 用例、参考证据、验收条件和评分协议一致时比较相邻运行指标。

示例请求体：

```json
{
  "intent_cases": [],
  "dialog_cases": [{
    "case_id": "refund-reference",
    "question": "退款审核一般需要多久？",
    "reference_evidence": ["退款申请提交后，系统会在 1-3 个工作日内审核。"],
    "acceptance_criteria": ["保留工作日单位", "区分审核与到账"]
  }]
}
```

当前网页的内置对话评测调用编排器。多轮 Redis 记忆验收使用完整 `/chat` API 路径，任务操作验收按[结果验收设计](TASK_RESOLUTION_DESIGN.md)检查业务最终状态。
