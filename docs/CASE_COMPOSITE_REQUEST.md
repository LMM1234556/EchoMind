# 一条消息里的多个问题如何得到逐项回答

更新：2026-11-15。本文整理复合诉求从漏答发现、原因定位、方案改进到真实复测的完整过程。

## 问题与目标

客服消息常同时包含多个诉求。例如：“密码忘了怎么重置，还有电子发票多久能开好？”用户需要两项都得到回应：密码重置可以依据账户安全文档回答，发票时限需要进一步核实。

60 条首次回答覆盖检查中，27 条严格通过、19 条部分完成、13 条未通过，另有 1 条因预算控制未完成。失败分析将复合诉求覆盖列为优先改进项。这些问题来自项目演示场景和人工审核的合成样本。

## 定位与取舍

排查时分别检查意图、Agent 路由、检索输入、候选文档和最终回答。Technical 与 Billing 同时参与，也可能在检索和取证时遗漏某个子问题。因此，改动重点放在“每项诉求是否拥有自己的证据状态”。

方案采用三个步骤：

1. 识别边界明确的子问题，保留错误码、金额与原始条件。
2. 各子问题分别检索和选择证据，记录充分依据、知识缺口或选择器异常。
3. 将分项结果交给生成模型，有依据的部分正常回答，待核实的部分给出具体下一步。

“退款审核还有几天能完成”属于同一诉求；“发票上还有退款信息”属于描述。口语连接词需要结合主题与提问特征判断，保持这些输入的完整性。

## 验收条件

| 检查 | 通过条件 |
|---|---|
| 诉求覆盖 | 密码与发票两项均得到回应 |
| 业务依据 | 重置指引来自账户安全资料，具体发票天数依据对应政策确认 |
| 证据来源 | 所选来源属于本次候选范围 |
| 局部异常 | 某项取证失败时，该项进入核实路径，其他已支持项继续回答 |
| 操作真实性 | 建议、交接与实际执行分别表述 |

## 已有验证

### 网页发现的新表达与两次真实复测

2026-11-15，网页输入“密码忘了怎么重置？还有，发票申请后多久能开好？”时，回复仅说明依据不足，遗漏密码重置。Trace 显示整句按发票主题取证，最终证据为空。

原因是问号与逗号使“还有”成为独立片段，主题检查将这个连接词当成未知诉求，进而保留整句查询。修复只跳过完整匹配的独立连接词，保留带实际内容的未知诉求检查。密码与发票分别取证，账户安全文档支持重置指引，发票时限保留知识缺口。

| 阶段 | 观察到的结果 | 改进与状态 |
|---|---|---|
| 原始网页请求 | 缺口说明覆盖整条消息，密码问题漏答 | 定位分句与主题收窄 |
| 标点修复后首次复测 | 两项均被回应；发票段补充“通常需要经过审核流程” | 为缺少依据的流程描述补充约束 |
| 约束调整后第二次复测 | 按文档给出重置指引，发票时限提示人工核实 | 助手逐项核对通过，负责人复核待确认 |

两次复测使用相同问题、六篇知识文档、`qwen3.6-plus` 模型别名和全新用户及会话。每次前台记录 3 次应用层模型调用，分别为意图识别、证据选择和回复生成；第二次后端总耗时 41,745.3 ms。逐题回复与 Trace 见[标点复合提问回归](COMPOSITE_PUNCTUATION_REGRESSION_20261115.md)。

同主题退款原题另完成一次真实请求：回复保留审核 1–3 个工作日、通过后 5–7 个工作日退回原支付账户，助手核对与文档一致，负责人复核待确认。[原始回复与 Trace](../backend/evaluation/reports/key_001_first_run_20261115.json)。
