# 口语复合请求分项取证

日期：2026-11-13。

## 问题与改动

原拆分规则主要依据标点和“另外”“同时”等连接词。“密码忘了怎么重置还有电子发票多久能开好”“登录提示401顺便问100积分能抵多少钱”及换行列出的请求会保留为整句，取证阶段容易只覆盖一个主题。

本轮在[查询路由](../backend/core/knowledge_routing.py)中共用明确子句解析：

1. 将换行作为显式边界，支持“还有”“顺便问”“还想问一下”等追加表达。
2. 口语连接的两侧分别检查询问或故障信号，区分追加诉求和普通描述。
3. 各子句均能映射到已定义知识主题、涉及不同主题且总数为 2–3 项时，执行原分项取证流程。
4. 单一主题、未知主题和缺少可靠边界的输入继续保留原文。
5. 领域收窄遇到无法归类的目标时保留完整请求，保留错误码、金额和其他上下文。

原检索工具、标题检查与 Evidence Selector 继续对每项取证；选择器错误与知识缺口分别记录。

## 行为示例

| 输入 | 处理 |
|---|---|
| 密码忘了怎么重置还有电子发票多久能开好 | 分别处理密码与发票；密码可以使用账户安全证据，发票时限保留知识缺口 |
| 登录提示401顺便问100积分能抵多少钱 | 分别检查技术故障与积分规则 |
| 配送时效和退款时效分行输入 | 分别检索配送和退款资料 |
| 发票上还有退款信息 | 作为完整描述保留 |
| 退款审核还有几天能完成 | 作为一个退款问题保留 |
| 登录401订单重复扣款99元 | 保留原文，交给既有链路处理 |
