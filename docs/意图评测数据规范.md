# 意图评测数据规范

## 1. 为什么不能直接报告现有准确率

代码中的 Few-shot 模板、关键词 Pattern 和开发期回归用例都参与过系统调试。若把这些内容直接当作正式测试集，会产生数据泄漏，准确率会偏高。正式指标必须来自冻结规则后独立收集、人工复核且没有进入模板的测试样本。

## 2. 标签状态

- `draft`：候选标签，尚未人工确认，不参与准确率计算。
- `verified`：人工检查了文本、标签和歧义，填写 `reviewer` 后才可参与评测。
- `rejected`：问题本身含义不清、同时包含多个无法确定主次的意图，或不适合当前标签体系。

仓库中的 `backend/evaluation/data/intent_eval_candidates.json` 已形成首批人工复核的开发集种子；它用于改进和回归检查，不得作为独立测试集报告准确率。`backend/evaluation/data/intent_test_candidates_v1.json` 仍是未复核的测试候选池。

## 3. 标注原则

1. 优先选择细粒度意图。例如“退款多久到账”标为 `refund`，不能标为宽泛的 `billing`。
2. 通用意图只处理没有对应细粒度类别的消息。例如只说“账单看不懂”可标为 `billing`。
3. 一条消息包含多个并列诉求时，应标记主诉求；无法确定主诉求时拒绝该样本，另建多意图路由评测集。
4. 不根据当前模型输出反向修改标签。标签依据业务定义，而不是模型预测。
5. 测试集文本不得复制 `_TEMPLATES`、关键词 Pattern 或已经反复用于调试的问题。

### `escalation` 与 `human_handoff` 的边界

- `human_handoff`：用户明确要求人工、真人、人工坐席或真人客服。
- `escalation`：用户要求主管、负责人、经理或更高级别介入处理，但不是普通的转人工请求。
- 单纯表达不满、没有要求升级或人工介入时，标为 `complaint`。

例如，“机器人解决不了，请接人工坐席”标为 `human_handoff`；“请把问题升级给主管处理”标为 `escalation`；“你们的处理结果让我很不满意”标为 `complaint`。

### `account` 与 `account_security` 的边界

- `account`：正常维护姓名、邮箱、绑定手机号等账户资料。
- `account_security`：存在账户被盗、异常登录、密码泄露、密码重置、两步验证等安全风险。

例如，“更换绑定手机号”标为 `account`；“陌生设备登录了我的账号”标为 `account_security`。不要因为手机号、邮箱属于敏感信息，就把所有资料修改都标成安全事件。

## 4. 建议规模与切分

“500 条”不是天然正确的目标，关键是类别覆盖和独立性。当前 19 个意图若机械平均，每类约 26 条；对于容易混淆的类别仍可能不足。建议分阶段建设：

- 第一阶段：每类至少 10 条已复核样本，用于发现标签定义问题。
- 第二阶段：每类至少 20 条，并增加口语、错别字、省略表达和相邻类别难例。
- 第三阶段：达到约 500 条后冻结测试集；后续修复只能使用训练集和开发集。

推荐切分为 70% `train`、15% `dev`、15% `test`。正式报告只使用从未参与调参的 `test`。

## 5. 独立测试集冻结流程

测试候选池以提交 `3aeca2011262594b1a6b8f774795909f3df9dbdf` 作为待测模型基线。该候选池共 95 条，覆盖 19 个意图，每类 5 条。冻结过程必须遵守：

1. 在不运行模型、不查看预测结果的前提下，由项目负责人逐条复核文本与标签；有歧义的样本标为 `rejected`，不得为了凑数量强行归类。
2. 复核通过的记录改为 `label_status: verified`、`split: test`，并填写 `reviewer`。
3. 完成人审后记录文件 SHA-256，形成 `intent-test-v1`，此后不得改写原测试文本或标签。
4. 冻结后只执行一次基线评测。发现错误时，把错误模式转成新的开发样本进行修复，不得用原测试样本调提示词、关键词、Few-shot 或阈值。
5. 后续需要复测改进效果时建立新版本测试集，或在完全不改动 v1 的条件下报告 v1 回归结果。

这 95 条文本由 AI 起草，即使经过人工复核，也只能构成受控的合成测试集，不能代替真实客服流量。简历或面试中应如实说明数据来源，不能把结果表述为线上真实业务准确率。

## 6. 指标

- `Accuracy`：全部样本中预测正确的比例。
- `Macro-F1`：先分别计算每个意图的 F1，再平均，避免大类别掩盖小类别失败。
- 每类 Precision、Recall、F1：用于定位退款/账单、登录/账户安全等混淆。
- 混淆矩阵：查看错误主要流向哪个相邻类别。

仅报告点估计仍不充分。样本规模增大后应同时给出置信区间，并保留模型、提示词、数据版本和运行日期。

## 7. 校验命令

在 `backend` 目录执行：

```powershell
python -m evaluation.intent_dataset evaluation/data/intent_eval_candidates.json
```

输出中的 `scoreable_total` 只有在人审完成、`label_status` 改成 `verified`、填写 `reviewer` 并分配到 `dev` 或 `test` 后才会增加。

测试候选池还需同时与开发集比较，检查完全重复文本：

```powershell
python -m evaluation.intent_dataset evaluation/data/intent_test_candidates_v1.json `
  --compare evaluation/data/intent_eval_candidates.json
```

在人审和冻结完成前，测试候选池的 `scoreable_total` 必须保持为 `0`，不得调用意图识别模型进行预测。
