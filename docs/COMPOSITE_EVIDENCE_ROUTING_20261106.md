# 复合诉求分项取证优化

日期：2026-11-06

## 问题来源

60 条回答覆盖评测中，复合诉求共 8 条，严格通过 1 条。主要现象是同一句包含两个业务问题时，检索链路只保留一篇证据，导致另一项规则未被回答。例如：

- 登录 401 排查 + 积分换算；
- 标准配送时效 + 异常订单所需信息；
- 加急配送费用 + 退款到账时效；
- 密码重置指引 + 发票办理时限知识缺口。

## 本次实现

1. 仅对存在明确标点或连接词、且各子句可映射到不同知识主题的请求做确定性拆分。
2. 每个子问题独立执行检索、标题门控与证据选择，最多保留 3 篇最终证据。
3. 并行执行各子问题的检索，避免串行放大端到端等待时间。
4. 将每个子问题标记为 `accepted` 或 `insufficient`，要求生成阶段逐项回答；知识缺口继续明确说明。
5. 单一主题、主题不明确或没有可靠分隔符的输入保持原有处理方式。

## 安全边界

- 文档标题白名单继续约束可引用证据；召回候选不会直接成为业务事实。
- 电子发票时限、重复扣款规则等当前知识库缺口不会借用近似文档补答。
- “登录401订单重复扣款99元”等无法可靠划界的文本不会被强制拆分。
- 原 60 条正式评测结果保持为改动前基线，不用离线回归推断线上指标提升。

## 验证结果

- 复合检索与 Agent 相关回归：53/53 通过。
- 完整离线回归：202/202 通过。
- 新增覆盖：双文档完整命中、支持项与知识缺口并存、同主题不拆分、无分隔符不拆分、旧单问题门控兼容。
