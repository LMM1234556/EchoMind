## 运行中发现并修复的问题

401 用例首次运行时，意图被正确识别为 `technical_login`，但置信度为 `0.715`，低于旧的 `0.8` 预取阈值，导致生成模型跳过 RAG。修复后，所有具体业务意图均执行一次确定性知识预取；候选是否充分由后续证据门控判断。预取完成后移除 RAG 工具，避免生成模型重复检索。

修复后的全量自动化回归结果为 `138 passed`。

## 验证范围

- 三条样本验证有据回答、技术选证和知识缺口三个关键分支。
- 401 回答虽然证据选择正确，但同时结合了 Technical Skill 中的通用排查规范，篇幅和场景聚焦仍可优化。
- 供应商超时、限流、断网与无效 JSON 分支由自动化替身测试覆盖；真实服务故障的观测另行记录。

## 回复依据复测

随后增加系统级事实依据规则，并把交给回复模型的 RAG 内容缩减为最终选中文档的标题和正文。动态 Skills 提供流程、安全规范和通用建议；平台业务事实依据选中的知识文档生成。

使用“登录报 401 时可以尝试重新设置密码吗？请只回答这个问题。”进行一次真实复测：

- 证据门控：`semantic_topk_selected`

本条运行态检查中，回复符合选中文档支持的内容；生成忠实度的分布由专门的回答评测集衡量。
