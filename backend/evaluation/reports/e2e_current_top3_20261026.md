## 未通过场景

1. `greeting`：回答内容符合问候和能力介绍契约，但意图输出为 `request`，而固定标签为 `greeting`。
2. `multi_agent_payment_login`：回答同时覆盖 401 和重复扣款，实际执行 Technical 主 Agent + Billing 辅助 Agent；固定用例预期 `payment_issue`、Billing 主 Agent + Technical 辅助 Agent，意图和主辅分配因此未匹配。Trace 中技术检索证据充分、账单检索证据不足，汇总证据状态与固定用例预期不同，回答契约检查也未通过。
3. `multi_turn_refund_memory` 第 1 轮：退款意图和 Billing 路由正确，但“请记住订单号并正在申请退款”没有足够政策事实问题，Evidence Selector 拒绝候选；系统返回无证据模板，未满足该旧用例要求的回答词面。第 2 轮正确利用同一会话并回答到账时效。

本轮据此优先检查问候意图、复合请求的主导规则与分领域证据，以及记忆指令的独立处理。复合用例中两个 Agent 都已参与，后续分别评价诉求覆盖、主辅职责和证据状态。第三项同时暴露旧综合用例契约与当前严格证据门控之间的语义冲突，保留当前标签与结果用于对照。

2026-11-05 根据本报告对应的原始 JSON 核对并更正场景解释；运行数据、标签、通过率和模型调用记录保持原样。
